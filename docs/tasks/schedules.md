# 定时计划与时间语义

[文档总目录](../README.md)

> 规格版本：2.8.0；状态：待实现的规范性设计。MUST/必须表示实现及验收要求，不能理解为现有功能。

## cron v1

五字段：分、时、日、月、周。分 0–59、时 0–23、日 1–31、月 1–12、周 0–6（0=周日）。支持 `*`、`a-b`、逗号列表、`*/n` 或 `a-b/n`，禁止秒、年、名称、L/W/#。日和周都非 * 时采用 OR 匹配，需在预览中提示。

timezone 使用有效 IANA 名称，默认 Asia/Shanghai。计算持久化 UTC fire_at，唯一键 `(schedule_id, scheduled_at)` 保证单次触发记录。

## DST 与停机

夏令时不存在的本地时刻跳过；重复本地时刻只触发第一次，避免双执行。misfire=skip 丢弃停机期间全部错过时刻；run_once 仅补最新一次，禁止补发所有历史时刻。

overlap=skip 在仍有非终态运行时丢弃本次；queue_one 最多保留一个最新待执行触发。计划变更取消未创建任务的旧触发；已创建任务保持原输入及委托。

当前同步实现的补发窗口为 24 小时。扫描只补发窗口内最新的错过时刻，并用一条跳过记录汇总更早时刻。计划行锁保护下一触发时间和待执行记录，创建 Task、步骤和触发关联在同一个 PostgreSQL 事务提交。重启时先以已关联的 Task 修正待执行记录，再处理错过时刻。重放同一 UTC 时刻沿用已有触发记录。

## 授权与更新

创建计划冻结执行委托，不保存浏览器会话。每次触发和每步执行检查完整账户/源凭证链。父级收权暂停新任务，follow_parent 不扩大旧执行委托。修改任务模板、输入、run_as 或范围需要重新核实授权。

schedule.delete 停止未来触发，不自动取消已有任务；任务取消使用独立接口。节点恢复先对账触发记录和任务幂等键，再处理 misfire。

计划支持使用固定 Capability 或 HTTP 同步 Skill 的 Workflow。创建时冻结原凭证、目标提供者和每个动作的授权来源。触发时只用原授权来源重建权限，每次创建独立 Task 委托。失去原授权或固定目标后，计划的 `next_fire_at` 为空，历史记录保留。所有者显式重新启用或修改已暂停计划时重新批准执行权限。其他更新保留已有委托，修改 Workflow 或输入需由所有者重新批准。
